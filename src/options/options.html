Sorting Preferences

Text & Number Sorting Mode:
Evaluates numbers by numerical value (e.g., Tab 1, Tab 2, Tab 10). Recommended for general browsing, tutorials, tickets, and reading lists.
Locale-aware sorting (case-insensitive, punctuation-ignoring) without numeric evaluation (e.g., Tab 1, Tab 10, Tab 2).
Known limitations & examples

Natural Numeric Sorting compares embedded numbers by numerical value instead of raw character codes (e.g., 2 < 10 rather than "10" < "2"). Learn more about Natural sort order on Wikipedia.

Known Limitations & Edge Cases:
  • Hexadecimal & UUID hashes: Digit sequences inside hashes are treated as numbers. For example, in 035DF... vs 4F35..., natural sorting sees 35 > 4 and places 4F35... before 035DF..., even though '0' < '4' alphabetically.
  • Zero-padded numbers with identical values: Strings like Tab 01 and Tab 1 have the same numerical value (1). Relative placement falls back to secondary collation rules rather than string length.
  • Complex version strings: Simple versions like v1.2 and v1.10 sort cleanly (1.2 < 1.10), but complex SemVer formats with prerelease tags (e.g., v1.2.0-rc1 vs v1.2.0) are compared segment-by-segment, not by true semantic version rules.
  • Technical URLs & Query strings: URL sorting also respects this setting. Cache-busting timestamps (?v=171000...), port numbers, or asset IDs in paths are compared numerically.

Recommendation: Use Natural sorting for general browsing, tutorials, tickets, and reading lists. Use Alphabetic sorting for developer workspaces with git commit hashes, raw hex files, or where numbers should be treated as text.
